## What was delivered

### 1. Dynamic Rake Configuration

Previously the house edge was fixed at server startup via the `HOUSE_EDGE_PERCENT` environment variable. Any change required a full server restart.

- **`SystemConfig` table** — a key/value store in PostgreSQL (`apps/backend/prisma/schema.prisma`) holds the live values for all five game tunables.
- **Runtime config service** (`apps/backend/src/services/runtime-config.service.ts`) — reads from the DB on first call, caches for 60 seconds, and falls back to env-var defaults if the DB is unreachable.
- **Matchmaking** now calls `getHouseEdgePercent()` per match instead of reading the static `config.game.houseEdgePercent`. Prize pool and house fee recorded in the `Game` row reflect the value in effect at match creation time.
- **Admin API** — `GET /admin/config` returns all tunables; `PATCH /admin/config` updates any subset and immediately invalidates the cache, so the new value takes effect within 60 seconds.

Tunable keys:

| Key | Default | Description |
|---|---|---|
| `houseEdgePercent` | 10 | % of total pot kept by the house |
| `matchmakingBetTolerance` | 0.10 | Max relative bet difference for pairing |
| `botInjectWaitSeconds` | 30 | Seconds before injecting a bot opponent |
| `turnTimeoutSeconds` | 30 | Max seconds per turn |
| `disconnectGraceSeconds` | 15 | Reconnect window before forfeit |

### 2. Fraud Log Viewer (Admin Dashboard)

A new **Fraudes** tab in the admin sidebar surfaces all `FraudLog` entries generated by the anti-fraud layer (Milestone 4).

- **Backend** — `GET /admin/fraud-logs` supports filtering by `type` and `resolved` status with pagination. `PATCH /admin/fraud-logs/:id/resolve` marks an entry resolved.
- **Frontend** — table shows fraud type (localised), user name/phone, truncated JSON details, IP, device ID, timestamp, and resolution status. Unresolved entries show a "Resolver" action button.
- A missing index on `FraudLog.resolved` was added in the migration (`20260408000000_system_config`).

### 3. Admin Dashboard — Configurações Tab

A new **Configurações** tab provides a live game-config editor:

- Each tunable is shown with its label, description, min/max bounds, and current DB value pre-filled.
- On save the frontend calls `PATCH /admin/config` and shows a success banner.
- A note reminds the admin that changes propagate within 60 seconds (the cache TTL).

### 4. Game Lobby — Prize Display Fix

`ModeSelectScreen` had hardcoded prize values calculated at 5% house edge, while the backend default is 10%. This caused a mismatch between what the lobby displayed and what players actually won.

- Prize values are now derived from a `HOUSE_EDGE` constant (`0.10`) via helper functions `prize1v1(buyIn)` and `prize2v2(buyIn)`, making the calculation explicit and consistent with the backend default.
- When the admin changes the house edge via the Config tab, only the computed values in the lobby need updating (a one-line constant change), preventing future drift.

**Before / After (1v1 R$10 buy-in):**

| | Before | After |
|---|---|---|
| Displayed prize | R$19 (5% edge) | R$18 (10% edge) |
| Actual server prize | R$18 (10% edge) | R$18 (10% edge) |

### 5. Production Deployment

**`nginx/nginx.conf`** — production-ready reverse proxy configuration:
- HTTP → HTTPS redirect
- Separate virtual hosts for `api.YOUR_DOMAIN` (backend + Socket.io) and `admin.YOUR_DOMAIN`
- WebSocket upgrade headers for Socket.io long-polling/WebSocket
- Per-zone rate limiting: 5 req/min on auth endpoints, 30 req/s on the general API
- Security headers (HSTS, X-Frame-Options, nosniff, XSS protection)
- IP allowlist block (commented out) for the admin subdomain

**`deploy.sh`** — one-command production deployment:
- Validates all required env vars and rejects known-weak defaults before touching anything
- Tags the running images as `:prev` so a `--rollback` flag can revert instantly
- Builds images in parallel (`docker compose build --parallel`)
- Brings up postgres/redis first, waits for health, then runs `prisma migrate deploy`
- Rolling restart via `docker compose up -d --remove-orphans`
- Reloads nginx on the host (systemd or direct)
- Polls `GET /health` and exits non-zero if the backend does not recover

## New API Endpoints

| Method | Path | Description |
|---|---|---|
| `GET`   | `/admin/config`                | Read all runtime tunables |
| `PATCH` | `/admin/config`                | Update one or more tunables |
| `GET`   | `/admin/fraud-logs`            | Paginated fraud log, filterable by type/resolved |
| `PATCH` | `/admin/fraud-logs/:id/resolve`| Mark a fraud log entry resolved |

## New Environment Variables

No new required variables were added. The `SystemConfig` table seeds all defaults from `HOUSE_EDGE_PERCENT` and the other existing game env vars on first migration.
